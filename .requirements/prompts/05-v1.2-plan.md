# AI Companion Core V1.2 实施方案

> 版本目标：在 V1.1 的流式工作流、多模型 Adapter、Tool Planning 与 Debug Workbench 基础上，接入可开关的 Tavily Web Search Tool；将 Demo 聊天主界面升级为基于 AI SDK UI 的可用聊天体验；并以实际代码校准文档。
>
> V1.2 只有两个阶段：阶段 1 实施 Web Search；阶段 2 实施 Demo UI、来源展示与文档收口。
>
> 本版本不改变 `packages/ai-core` 的纯 SDK 边界，不引入用户系统、鉴权、生产部署、LangChain、LangGraph 或 MCP。

## V1.2 核心目标

用户在 Demo 中开启 Web Search 后，伴侣按需联网：

```txt
用户输入
↓
Tool Planning
↓
是否选择 web_search？
├── 否 → 直接生成最终回复
└── 是
    ↓
    生成优化后的 query 与搜索参数
    ↓
    Tavily Search
    ↓
    标准化 Search Result
    ↓
    写入 Tool Context
    ↓
    最终流式回复
    ↓
    Demo 展示 Sources
```

V1.2 的完成不是“每条消息都先搜索”，而是：

> 当 Web Search 被启用且当前模型具有工具调用能力时，既有 Tool Planning 负责判断是否联网、生成检索语句与参数；只有需要时才调用 Tavily，并基于可追踪来源完成最终回复。

## 关键设计决定

### 1. Web Search 是 Tool，不是 Workflow 特判

禁止在 `SimpleChatWorkflow` 中写：

```ts
if (needSearch) {
  // 直接调用 Tavily
}
```

正确结构：

```txt
ToolPlanningProvider
↓
ToolPlan
↓
ToolRegistry
↓
web_search Tool
↓
WebSearchProvider（首个实现：tool-web-search-tavily / TavilyWebSearchProvider）
↓
ToolResult
↓
Final Response
```

Workflow 只知道“计划并执行工具”，不知道 Tavily、HTTP 或 API Key。

### 2. 不新增独立 Search Planner

V1.1 的 Tool Planning 已负责：

```txt
no_tool
或
 tool_calls
```

V1.2 仅将 `web_search` 作为可选工具注入。

```txt
用户：最近 OpenAI 有什么值得关注的吗？
→ web_search({ query: "OpenAI latest news" })

用户：解释 Promise.all。
→ no_tool
```

是否搜索与 query 改写由 Tool Planning 决定；检索工程参数（topic、country 等）由具体 WebSearchProvider adapter 处理，不是 `web_search` 的工具参数。

### 3. 搜索生效的三项前置

```txt
1. webSearchEnabled = true
2. WEB_SEARCH_BACKEND 指向已实现的 adapter，且对应 API Key 有效
3. 当前有效模型 capabilities.toolCalling = true
```

```txt
- 任一条件不满足时，不注册 / 不注入 web_search Tool
- Tool Planning 不可选择 web_search
- Demo 配置区必须显示具体不可用原因（含 unsupported_backend）
- 默认模型 capability 需显式配置，Ollama 也需要宿主 override 后才可能触发工具调用
```

### 4. Sources 是 Host DTO，不回写 Core Output

Core 的 `ChatWorkflowOutput` 和 `workflow:finish` 由 Core 产生，Demo Host 不得在接收后回写或修改其语义。

正确分层：

```txt
Core ChatWorkflowOutput / tool:result
↓
Demo Host Wire Mapper / UI Adapter
↓
DemoWorkflowMetadata.webSearch
↓
Sources UI
```

```ts
interface DemoWorkflowWebSearchMetadata {
  query: string;
  provider: WebSearchProviderId;
  sources: WebSearchSource[];
  responseTimeMs?: number;
  usage?: {
    credits?: number;
    requestId?: string;
  };
  retrieval?: WebSearchRetrievalMetadata;
}
```

`RunDebugPanel` 提供 **Web Search Log**（`web-search-debug-log.ts`）：展示 Planner query、`retrieval.retrievalQuery`、每次 Tavily 请求的 `retrieval.requests[]` params。

约束：

```txt
- `DemoWorkflowWebSearchMetadata` 只属于 Host / Wire DTO / UI State
- 不扩写或回写 Core 的 ChatWorkflowOutput.metadata
- 仅当本轮 web_search 成功时填充 sources
- 搜索失败时，UI 从 tool:result failure 或 Trace 读取失败状态
- Sources 禁止从模型自然语言正则提取 URL
```

### 5. Search DTO 必须 Provider 无关

`packages/tool-web-search` 公开稳定类型（Provider 无关 core）：

```ts
export type WebSearchProviderId = string;

export interface WebSearchInput {
  query: string;
  maxResults?: number;
}

export interface WebSearchSource {
  id: string;
  title: string;
  url: string;
  snippet: string;
  score?: number;
  faviconUrl?: string;
  publishedAt?: string;
}

export interface WebSearchResult {
  provider: WebSearchProviderId;
  query: string;
  sources: WebSearchSource[];
  responseTimeMs?: number;
  usage?: {
    credits?: number;
    requestId?: string;
  };
  retrieval?: {
    attempts: number;
    primaryReason: string;
    fallbackUsed: boolean;
    retrievalQuery?: string;
    requests?: Array<{
      attempt: number;
      reason: string;
      provider: WebSearchProviderId;
      params: Record<string, string | number | boolean>;
    }>;
  };
}
```

Tavily adapter（`packages/tool-web-search-tavily`）返回：

```ts
provider: "tavily";
```

约束：

```txt
- snippet 必须限长，不传 raw_content
- publishedAt 仅在 Provider 可靠提供时填写
- Tavily 特有类型不得泄漏进 ai-core 或公共 Wire DTO
- Search Result 不写入长期 Memory
```

### 6. 搜索结果进入最终回答

`web_search` 结果经既有 `buildToolFollowUpMessages()` 进入 Tool Context。

不得在 `SimpleChatWorkflow` 或 `persona-prompt-builder` 中写：

```ts
if (tool.name === "web_search") {
  // Search 特判
}
```

`packages/tool-web-search` 负责提供模型可读的结果摘要和约束（`usageInstructions`），须保持跨领域通用：

```txt
- 结果来自外部 Web Search，不是系统内置知识
- Today is YYYY-MM-DD（运行时当天日期）；涉及今天、最新、当前、最近等相对时间时，以该日期理解
- 只使用 search.sources 能够支持的事实
- 不得虚构 URL、标题、发布时间、人物、状态、分数、具体数字或引用
- 来源彼此冲突时，应明确说明冲突，不得自行补全结论
- 搜索结果不足以确认时，应说明信息不足或不确定，不得猜测
- Provider answer（如存在）仅作辅助信息，不是唯一事实来源
- 最终面向用户的自然语言回复由 Companion 基于结构化 search.sources 组织
```

以下内容保留在 Tavily adapter 的检索策略与结果排序中，**不属于**模型层 `usageInstructions`：

```txt
- 从候选来源中识别并排序未来事件日期
- 对延期、取消、票务等文本做检索质量与来源排序处理
- 针对特定查询做 CJK、财经、新闻、时间窗口与 fallback 策略
```

### 7. 搜索失败不能伪造成功

```txt
Tavily 超时 / 401 / 429 / 5xx
↓
ToolResult 记录失败
↓
Trace / Debug Timeline 可见 provider、错误类别、请求摘要
↓
最终模型可按 Tool Policy 诚实说明，或继续普通回答
↓
Demo 显示 search failed，不展示伪造 Sources
```

空结果是成功但 `sources = []`，模型不得声称找到资料。

V1.2 不做 Tavily 自动 fallback 到第二家搜索服务。

# 阶段 1：Tavily Web Search Tool、Tool Planning 接入与工作流可观测性

## 目标

以 Tavily 为首个 Search Provider，完成可开关、可规划、可执行、可追踪的 `web_search` Tool；保持 Search 与 Core Workflow 解耦。

## 完成标准

```txt
- TAVILY_API_KEY 只由宿主读取并注入
- ai-core 不新增 Tavily SDK / HTTP / env 依赖
- 新增 packages/tool-web-search（Provider 无关 core）与 packages/tool-web-search-tavily（Tavily adapter）
- 关闭搜索、Provider 未就绪、toolCalling=false 时，模型不可见 web_search
- 开启搜索且前置满足时，Tool Planning 可按意图选择 web_search
- Planner 可生成优化 query（不含年份）；检索参数由 adapter 策略决定
- Tavily 响应标准化为 WebSearchResult
- 搜索结果进入最终回答的 Tool Context
- tool:call / tool:result / Trace / Wire DTO 可观测 query、结果、来源与失败
- Host 能从成功 ToolResult 派生 DemoWorkflowWebSearchMetadata
- executeWorkflow() 与 streamWorkflow() 均兼容
- 原有 Memory Search、时间、情绪等工具行为不回归
- 确定性验证与真实联网验证均具备
```

Demo Host 读取 `WEB_SEARCH_BACKEND`（默认 `tavily`）与 `TAVILY_API_KEY`，经工厂构造：

```ts
const provider = createWebSearchProviderFromEnv(env); // → TavilyWebSearchProvider
createWebSearchTool({ provider });
```

再经既有 Tool Registry / Tool Provider 注入 `createCompanionCore()`。

Tavily HTTP 映射与检索策略仅存在于 `tool-web-search-tavily`；底层 Tavily 类型不能泄漏出 adapter 边界。

检索策略（adapter 内部，Planner 不可见）：

```txt
Query 预处理：剥离 query 中早于当前年的四位数年份
Primary：默认 general + start_date=当年-01-01；CJK → country=china + auto_parameters=false；财经/新闻词切换 topic
来源排序：解析 title/snippet 中的具体日期，优先今天及以后且未延期/取消的场次
Fallback：primary 质量 poor 时再搜一次，清除 start_date、auto_parameters=true
每次搜索最多 2 次 Tavily 调用；retrieval.requests 记录完整 HTTP params
```

### 2. web_search Tool

工具名固定：

```txt
web_search
```

输入 schema（query-only）：

```ts
{
  query: string;
  maxResults?: number;
}
```

Tool description 必须指导 Planner：

```txt
- 实时信息、新闻、价格、天气、赛程、当前身份、法规、产品现状、外部来源验证时使用
- 稳定常识、纯解释、写作、翻译、情感陪伴、基础代码概念默认不使用
- query 为简洁检索语句，不机械复制用户原句
- query 不得包含年份；时效由系统处理
- 调用后最终回答以结果为依据；来源不足时说明不确定
```

检索工程参数（topic、start_date、country、auto_parameters 等）由 Tavily adapter 内策略层决定，不是 `web_search` 工具参数。

### 3. Tool Planning 接入

不新增 `SearchPlanner`，不在 ai-core 增加 Search 专用 Workflow 分支。

V1.2 通过：

```txt
1. 条件满足时才向 ToolRegistry 注册 web_search
2. web_search description 提供何时搜、如何改写 query 的约束
3. parameters schema 仅含 query（及可选 maxResults）
4. 复用 ToolPlanningProvider 的 model.generate({ tools, requiredCapabilities: { toolCalling: true } })
```

不得为了 Web Search 修改 Planner 为 Provider 特判逻辑。

## V1.2 关键设计原则

1. Web Search 是可注入 Tool，不是 Workflow 特判；
2. 是否搜索、query 改写与参数由既有 Tool Planning 决定，不新增平行 Search Planner；
3. 搜索关闭、Tavily 未就绪或 toolCalling=false 时，不得向模型暴露 `web_search`；
4. Tavily 是首个 adapter，不是 Core 固定依赖；Host 可通过 `WEB_SEARCH_BACKEND` 切换已实现的 provider；
5. Search DTO 必须 Provider 无关；
6. Sources 由 ToolResult 经 Host 派生，Host 不回写 Core Output；
7. 搜索引用约束在 `packages/tool-web-search`，不在 ai-core 特判；
8. 不直接使用 Tavily answer 代替 Companion 最终回复；
9. 搜索失败、空结果与无 toolCalling 能力必须可观测，不能伪造联网成功；
10. 搜索结果不写入长期 Memory；
11. AI SDK UI 只在 Demo Host，阶段 2 固定 `useChat + Custom Transport`；
12. 保留 V1.1 NDJSON 与 Debug Workbench；
13. Chat Surface 与 Debug Surface 分层；
14. 确定性验证与真实 E2E 分层；真实 E2E 是完成证据，不替代 CI；
15. 文档只描述已实现的真实行为。
