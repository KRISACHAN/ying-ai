# AI Companion Core V1.2 实施方案

> 版本目标：在 V1.0 / V1.1 已完成的 Core SDK、模型策略、流式 Workflow、Tool Planning、Ollama Adapter 与 Debug Workbench 基础上，完成「可替换的 Web Search 工具接入」与「基于 AI SDK UI 的 Demo 聊天体验升级」。
>
> V1.2 只包含两个阶段：
>
> 1. Web Search Tool 实施；
> 2. Demo UI 升级与项目文档收口。
>
> 本文是 V1.2 唯一需求基线。后续 `.requirements/stages/v1.2/`、`.code-reviews/v1.2/` 与实现代码均以本文为准。

## V1.2 核心目标

```txt
用户提出需要时效或需核实的信息
↓
当前对话允许 Web Search 且基础设施可用
↓
Tool Planning
↓
web_search Tool
↓
外部搜索 Provider
↓
标准化搜索结果与来源
↓
Final Response
↓
AI SDK UIMessage Stream
├── 流式文本
├── 搜索 / 工具状态
└── 可点击来源卡片
```

V1.2 完成后，Demo 应支持：

1. 当前对话可决定是否启用 Web Search；
2. 模型在新闻、天气、价格、近期事件、公开资料核实等场景选择 `web_search`；
3. 搜索结果以统一结构进入最终回答，不直接注入供应商原始响应；
4. 最终回答可基于搜索结果生成，UI 可展示来源卡片；
5. 聊天 UI 使用 AI SDK UI 的 `useChat`、`UIMessage` 与 UIMessage Stream；
6. Workflow、Tool、查询词、来源、Runtime 与错误仍可在 Debug Workbench 中查看；
7. 不破坏既有 `CompanionCore`、`ToolRegistry`、`streamWorkflow()`、Memory scope、会话持久化与模型 Adapter 边界。

## 关键架构决策与冻结约束

### 1. Web Search 是现有 Tool 系统的外部 Adapter

V1.2 不新增第二套 Agent Tool 体系，不在 Workflow 硬编码搜索分支。

```txt
apps/model-runtime-demo
  ├── 读取 TAVILY_API_KEY / WEB_SEARCH_*
  ├── 读取 conversation.webSearchEnabled
  ├── 创建 TavilyWebSearchClient
  └── 条件注册 web_search

packages/tool-web-search
  ├── WebSearchClient 抽象
  ├── WebSearchSource 标准结构
  ├── TavilyWebSearchClient
  └── createWebSearchTool

packages/ai-core
  └── 仅通过 ToolRegistry.list / execute 消费工具
```

`ai-core` 不导入 Tavily SDK、不读取 `TAVILY_API_KEY`、不理解 `search_depth`、不依赖 URL 搜索 API。

### 2. Tavily 是 V1.2 的首个 Provider，不是永久绑定

`packages/tool-web-search` 必须先定义供应商无关契约：

```ts
export type WebSearchTopic = "general" | "news";
export type WebSearchTimeRange = "day" | "week" | "month" | "year";

export interface WebSearchRequest {
  query: string;
  topic?: WebSearchTopic;
  timeRange?: WebSearchTimeRange;
  includeDomains?: string[];
  excludeDomains?: string[];
}

export interface WebSearchSource {
  id: string;
  title: string;
  url: string;
  snippet: string;
  publishedAt?: string;
  score?: number;
  faviconUrl?: string;
}

export interface WebSearchResponse {
  query: string;
  sources: WebSearchSource[];
  provider: string;
  durationMs?: number;
  metadata?: Record<string, unknown>;
}

export interface WebSearchClient {
  search(input: WebSearchRequest): Promise<WebSearchResponse>;
}
```

后续接 Exa、Brave、Serper、Bing 或内部搜索时，只新增 `WebSearchClient` 实现；不改 Workflow、Tool Definition、来源渲染或 `ai-core`。

### 3. 搜索结果是外部临时上下文，不是长期记忆

```txt
Web Search Result
├── 可进入本轮 Final Response 上下文
├── 可进入 Tool Result、Workflow Trace 与 Debug Run
├── 可作为本轮 UIMessage source parts
└── 不得写入长期 Memory / pgvector
```

不能只依赖模型自觉，必须工程化保证：

```txt
1. 本轮存在成功 web_search Tool Result 时，MemoryExtractionInput 传入：
   externalContextUsed: true
   excludedToolNames: ["web_search"]

2. Memory Extractor 的 system prompt 明确：
   不得将 web_search 来源中的外部公开事实写入长期记忆。

3. web_search Tool Result 不得作为 Extractor 的候选文本来源。

4. 仍允许提取用户明确表达的稳定偏好、个人经历、关系边界等内容；
   不能因一次搜索而禁用整轮用户记忆提取。
```

可选的来源事实剥离属于后续优化，不是 V1.2 必须项。

### 4. Web Search 采用双层门控

```txt
基础设施层
├── TAVILY_API_KEY 存在
├── WEB_SEARCH_ENABLED !== false
└── 当前实际 ModelProfile.capabilities.toolCalling === true

业务层
└── debug_conversations.web_search_enabled === true
```

语义：

```txt
环境变量 / key
→ 开发者控制系统是否有搜索能力

conversation.webSearchEnabled
→ 当前对话控制本轮是否允许外部搜索

默认 false
→ 避免误触、外部请求与费用
```

关闭或不可用时，**不注册** `web_search`，而不是注册 Disabled Tool。Planner 不应看到不可执行工具。

新增 migration：

```sql
ALTER TABLE debug_conversations
ADD COLUMN IF NOT EXISTS web_search_enabled BOOLEAN NOT NULL DEFAULT false;
```

新增或扩展 API：

```txt
GET   /api/conversations/[id]  → 返回 webSearchEnabled
PATCH /api/conversations/[id]  { "webSearchEnabled": true }
```

每条消息不重复提交开关；发送时以对话持久化值为准。

Demo Runtime 必须展示：

```txt
enabled
user_disabled
infra_unavailable
model_unsupported
```

### 5. Tool Definition、执行结果与错误语义

`web_search` 面向模型的 Definition 只暴露可控参数：

```ts
const webSearchDefinition: ToolDefinition = {
  name: "web_search",
  description:
    "搜索公开网页以获取近期、实时或需要核实的信息。适合新闻、当前事件、价格、天气、产品动态、公开资料核实。不要用于用户个人记忆、纯聊天或已有上下文可回答的问题。",
  parameters: {
    type: "object",
    properties: {
      query: { type: "string" },
      topic: { type: "string", enum: ["general", "news"] },
      timeRange: { type: "string", enum: ["day", "week", "month", "year"] },
      includeDomains: { type: "array", items: { type: "string" } },
    },
    required: ["query"],
    additionalProperties: false,
  },
  metadata: { tags: ["web", "search", "external", "time-sensitive"] },
};
```

以下参数由宿主配置固定，模型不能自由决定：

```txt
searchDepth
maxResults
includeRawContent
retry
request timeout
provider-specific options
```

标准化与安全约束：

```txt
- url、title、snippet 为必须字段；
- URL 仅允许 http / https，非法 URL 丢弃；
- snippet 必须截断；
- V1.2 默认最多 5 条 source；
- 不返回原始 HTML、Markdown 全文或 raw_content；
- provider raw response 仅可出现在受限 server debug，不进 Prompt、UIMessage 或持久化来源结构；
- Tavily answer 不是可信最终回答，不能直接显示为伴侣结论。
```

错误分类可以通过既有 `TOOL_EXECUTION_FAILED` 承载，并在 metadata 记录稳定 domain code：

```txt
WEB_SEARCH_DISABLED
WEB_SEARCH_INVALID_QUERY
WEB_SEARCH_TIMEOUT
WEB_SEARCH_RATE_LIMITED
WEB_SEARCH_UNAUTHORIZED
WEB_SEARCH_PROVIDER_ERROR
WEB_SEARCH_NO_RESULTS
```

Adapter 内可对网络超时、429、5xx 有限重试；401 / 403 / 参数错误不得盲目重试。所有异常最终映射为 `ToolResult.ok = false`，不得透传原始异常栈。

### 6. Tool Planning 与 Final Response 保持分离

V1.2 必须沿用 V1.1：

```txt
Tool Planning
├── 只产出 no_tool / tool_calls
├── 可选择 web_search
└── 不生成面向用户的最终自然语言回答

Tool Execute
├── 调用 Tavily
├── 标准化来源
└── 发出 tool:call / tool:result

Final Response
├── 消费标准化 Tool Result
├── generate 或 stream 自然语言回答
└── 生成可读引用标记
```

约束：

```txt
- 当前实际模型不支持 toolCalling 时不注册 web_search；
- primary → fallback 后按既有策略重新评估能力；
- 默认不支持 Tool Calling 的 Ollama 配置不能尝试 web_search；
- 对话开关关闭时 Planner 根本看不到 web_search；
- Demo 必须展示模型能力与搜索不可用原因。
```

### 7. 外部事实约束不能压制 Companion 对话

对成功的 `web_search` Result，在 `formatToolResultForModel(result)` 或 Final Response Tool Context 中加入等价规则：

```txt
以下内容来自外部网页搜索，仅作为本轮参考资料。

对于由这些来源支持的外部事实性信息：
- 只能基于提供的 sources 概括；
- 不得补充来源未支持的具体事实、数字、日期、结论或链接；
- 使用 [1]、[2] 等编号时，编号必须对应 sources 顺序；
- 无法从 sources 确认时，应说明信息不足或无法确认；
- 不得把来源内容伪装为用户事实、长期关系记忆或系统事实。

你仍可保持既定伴侣 Persona、自然的情绪回应和对话历史承接，
但不得把这些回应伪装成搜索结论，也不得用 Persona 补全来源未支持的外部事实。
```

禁止使用过度宽泛的“回答只能基于 sources 概括”，避免压制正常陪伴、情绪回应与上下文承接。

无结果或失败时：

```txt
无结果
→ 可继续给出不依赖外部事实的支持性回应或澄清问题；
→ 不得声称已查询到具体结论。

失败
→ 必须坦诚未获得可靠外部资料；
→ 可基于已有对话继续回应；
→ 不得将模型猜测包装为刚搜索到的信息。
```

### 8. Core Event、Wire Event 与 UIMessage Stream 三层边界

```txt
CompanionCore.streamWorkflow()
  ↓
ChatWorkflowStreamEvent
  ↓
Demo Host Event Bridge
  ↓
AI SDK UIMessage Stream
  ↓
useChat<DemoChatMessage>()
  ↓
聊天 UI / 来源卡 / Debug Drawer
```

```txt
Core Event
→ 可含 Date、raw、内部调试字段

Wire Event
→ JSON-safe 宿主事件，保留作内部调试 / 合同验证

UIMessage Stream
→ 浏览器 useChat 消费的 UI 协议
```

Core 不依赖 AI SDK UI。Route 不得直接将 Core Event 原样塞进 UIMessage。

### 9. UIMessage、Conversation Store 与历史转换

```txt
Conversation Store / 数据库
→ 会话与 canonical message 的事实来源

useChat messages
→ 当前页面的 UI 渲染状态

Host Mapper
→ 只把 user / assistant text parts 转为 Core ChatMessage
→ source / tool / runtime / workflow data parts 不得进入 Core history
```

页面加载时从持久化会话恢复消息，再映射为 `DemoChatMessage`。

Demo 专属 UIMessage 可定义：

```ts
export type DemoChatMessage = UIMessage<
  DemoMessageMetadata,
  {
    workflow: DemoWorkflowData;
    tool: DemoToolData;
    webSearch: DemoWebSearchData;
    runtime: DemoRuntimeData;
  }
>;
```

约定：

```txt
text part
→ 用户与伴侣可见文本

source part
→ 标准化 WebSearchSource，用于来源卡

transient data-workflow
→ 当前步骤、加载状态、错误提示，不持久化

data-tool / data-webSearch
→ 本轮精简工具摘要，不携带 raw provider response

data-runtime
→ 最终模型、fallback、耗时等安全运行信息
```

### 10. 来源持久化关联与刷新恢复

来源不写入 `debug_messages`，而是保存在对应 Workflow Run 的安全结果 JSON 中。因此 V1.2 冻结一对一关系：

```txt
DebugWorkflowRun.assistantMessageId
→ DebugMessage.id
```

迁移语义：

```sql
ALTER TABLE debug_workflow_runs
ADD COLUMN IF NOT EXISTS assistant_message_id <与 debug_messages.id 相同类型> NULL
REFERENCES debug_messages(id) ON DELETE SET NULL;

CREATE UNIQUE INDEX IF NOT EXISTS debug_workflow_runs_assistant_message_id_unique
ON debug_workflow_runs (assistant_message_id)
WHERE assistant_message_id IS NOT NULL;
```

约束：

```txt
- 一个 completed workflow run 最多关联一条 assistant message；
- 一条 assistant message 最多关联一个 workflow run；
- failed run、输入拒绝、未生成 assistant 文本的 run 可保持 assistantMessageId = null；
- 删除 assistant message 时仅解除关联，不删除 workflow run；
- 禁止在 debug_messages 复制 Tool Result、sources、trace 或完整 UIMessage parts；
- 禁止通过“当前对话最新 run”猜测来源归属。
```

正常完成的写入顺序必须是单事务或等价原子语义：

```txt
1. Workflow 完成，得到 assistant text、Tool Result、Runtime、Trace；
2. 创建 canonical assistant debug_message；
3. 持久化 / 更新 debug_workflow_run；
4. run.assistant_message_id 指向该 assistant message；
5. 提交事务；
6. 仅提交成功后发送 workflow:finish / UIMessage 完成信号。
```

刷新恢复：

```txt
1. 查询 debug_messages；
2. 对关联 run 的 assistant message 批量查询 debug_workflow_runs；
3. 从 run 的标准化结果 JSON 读取 WebSearchSource[]；
4. 映射为该 message 的 source parts；
5. 每条 assistant message 只渲染自己的来源卡。
```

不能从模型文本中的 `[1]`、`[2]` 推断 URL。

### 11. `stop()` 的 V1.2 冻结语义

V1.2 的 `useChat.stop()` 只表示：

```txt
客户端停止读取 / 渲染当前 HTTP 流
```

它不表示：

```txt
服务端 Workflow 已取消
模型调用已取消
Web Search 已取消
后置 Safety / Summary / Memory 写回已取消
本轮 run 必须持久化为 aborted / partial
```

V1.2 不实现 Browser → Route → Workflow → Model / Tool Adapter 的 AbortSignal 透传。

唯一语义：

```txt
用户点击 stop()
↓
浏览器停止消费 UIMessage Stream
↓
UI 标记 stopped-locally
↓
服务端 Workflow 可能继续执行
↓
服务端自然完成时
→ 正常持久化完整 assistant message
→ 正常完成 workflow run
↓
刷新或重新打开对话
→ 可能看到服务端后来完成的完整回复
```

UI 必须区分：

```txt
客户端消费状态：streaming / stopped-locally / completed-client-side
服务端 Workflow 状态：running / completed / failed
持久化状态：pending / persisted / persistence-failed
```

停止后最低提示：

```txt
已停止在当前页面继续显示。
服务端可能仍在完成本轮回复；重新打开对话可查看最终结果。
```

V1.2 禁止：

```txt
- 浏览器 stop 后无确认地将 run 写为 aborted；
- 因客户端 stop 将 assistant text 写为 partial；
- 宣称模型 / 搜索已取消；
- 宣称已支持断线续传、服务端取消或继续生成；
- 以浏览器是否消费完流作为 Workflow 成败判定。
```

真正服务端取消留待后续独立版本，届时必须实现 AbortSignal 全链路传递、取消 Trace、partial 语义与竞态验证。

## 阶段 1：Web Search Tool Adapter 与搜索闭环实施

### 目标

通过既有 `ToolRegistry` 接入一个可替换的 `web_search`，让 Tool Planning 在条件满足时调用外部搜索，并让标准化来源进入最终回答、Workflow Trace 与宿主调试数据。

### 完成标准

```txt
[ ] 新增 packages/tool-web-search
[ ] ai-core 不新增 Tavily 依赖、不读 env
[ ] TavilyWebSearchClient 从宿主 TAVILY_API_KEY 创建
[ ] debug_conversations.web_search_enabled 默认 false 并可通过 API 修改
[ ] 仅基础设施可用、模型支持 Tool Calling、对话开关开启时注册 web_search
[ ] 成功 Tool Result 包含可序列化 WebSearchSource[]
[ ] 失败返回稳定 ToolResult 错误，不泄露 raw exception
[ ] 搜索结果不自动进入长期 Memory
[ ] 最终回答按来源约束生成，保留自然 Companion 对话
[ ] Runtime / Trace 可看开关状态、query、provider、耗时、来源数与失败原因

```

Route 负责：

```txt
1. 读取请求与 conversation（含 webSearchEnabled）；
2. 条件创建 Core 与 web_search Tool；
3. 调用 core.streamWorkflow(input)；
4. 消费 ChatWorkflowStreamEvent；
5. 通过 createUIMessageStream / createUIMessageStreamResponse 输出 UI 协议；
6. 原子持久化 assistant message 与 workflow run；
7. 仅完成持久化后结束正常 UIMessage Stream。
```

事件映射：

```txt
workflow:start
→ transient data-workflow { status: "started" }

step:start / step:end
→ transient data-workflow { step, status, summary? }

text:delta
→ UIMessage text-start / text-delta / text-end

tool:call
→ transient data-tool { status: "running", name, query? }

tool:result(web_search)
→ data-webSearch { status, query, provider, sourceCount }
→ 每个 WebSearchSource 对应 source part

tool:result(其他)
→ data-tool { status, name, ok }

workflow:finish
→ data-runtime / data-workflow 完成状态
→ 原子持久化成功后关闭流

workflow:error
→ UIMessage error + transient data-workflow error
```

硬性约束：

```txt
- Route 不得原样透传 Core Event；
- UIMessage raw data 不得回传 ai-core；
- UIMessage 不含 API Key、模型 raw response、stack、完整 provider raw response；
- source URL 只来自标准化 WebSearchSource；
- useChat 不是 Agent 编排器，不能替代 CompanionCore.streamWorkflow()；
- UIMessage 不是 Conversation Store 的真相来源。
```
